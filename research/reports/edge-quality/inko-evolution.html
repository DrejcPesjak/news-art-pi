From original Inko to the eight-pass candidate

The chain of changes, what each one saves, and which compromises remain visible.

1 · Original Inko532M generator + Qwen text encoder + Qwen VAE. Good scene quality; too much joint residency.
2 · Stream the weightsMixed 4/8-bit matrices, mapped embeddings and separate native CPU stages.
3 · Distill the trajectory24 guided teacher updates become eight single-pass student updates.
4 · Distill the decoderNew 16-channel tiny decoder replaces the heavy original decoder.

Start with the full pipeline, not only the generator

Starting points: the pinned Inko checkpoint and upstream implementation. These are upstream components, not models trained from scratch in this project.

At BF16, the original generator stored about 1015.66 MiB for 532,496,992 parameters. The 596M-parameter Qwen text encoder added 1136.88 MiB and the 126.9M-parameter VAE added 242.03 MiB. Their sum, 2394.56 MiB, excludes activations and runtime workspaces. Reducing output resolution alone could not solve this weight residency problem.

The released Inko recipe used 20 Euler steps and CFG 4.5. We used its existing first-20-layer Qwen conditioning convention, rather than inventing a new text representation. Caption preparation remains separate from model generation.

Pack weights and make residency explicit

Transformer matrices are quantized in groups of 64 input columns. Most block matrices use four bits; sensitive modulation matrices use eight. Small projections, biases and norms stay FP32. Groupwise Hessian error feedback, calibrated on real development trajectories, compensates some activation error. This is a bounded groupwise adaptation of GPTQ, not full-Hessian GPTQ.

The packed transformer occupies about 361.7 MiB on disk. The Qwen text assets occupy about 626.6 MiB, including a 296.75 MiB mapped embedding table from which only requested rows are gathered. Disk size is not peak process RAM.

At runtime we map the packed arrays, expand only the current matrix, execute optimized FP32 NCNN GEMM, and release unused workspace/mapped pages. This saves residency; it does not imply int4 arithmetic or a guaranteed speedup. Chunked attention avoids materializing all heads’ complete attention matrices together.

Keep a faithful decoder route first

For one image frame, a causal temporal convolution uses only its final temporal slice. We specialized the Qwen decoder to the first frame’s exact 2D operations and skipped temporal resampling that the original first-frame path also skips. This retained about 25.3M effective parameters, stored in 48.3 MiB FP16 NCNN weights.

Split graphs and complete row halos bound local convolution workspaces. Global attention still sees the full frame. This differs from approximate tiling of an entire attention-containing VAE. This decoder remains in the bundle as the quality fallback.

Teach eight steps to imitate twenty-four

We captured 192 short public captions from a pinned revision of Inko’s rollout caption dataset, added 144 handwritten scene combinations and eight development captions: 344 prompts total. No external image dataset was downloaded. The teacher generated all training trajectories locally at 384px.

The teacher took 24 steps with CFG 4.5. Each group of three teacher intervals supplied an average velocity target for one of eight coarse student intervals. Rank-32 adapters were trained across the transformer’s linear layers: 19,752,960 trainable parameters, merged into the dense model after training.

After 3000 updates, mean rollout latent relative RMSE on four development captions fell from 0.6934 to 0.4775. The adapter was selected on that development evidence, then quantized and calibrated again for its own activations. The numerical loss does not measure coherence. The fixed-grid teacher-state regression also does not guarantee the student behaves well on its own off-trajectory states.

The run resumed after checkpoint 1500 with a fresh optimizer following a corrected inference-cache bug. This is recorded explicitly rather than presented as one uninterrupted training run.

Train a decoder for Inko’s actual latent space

Stock TAESD expects four-channel Stable Diffusion latents, while Inko uses sixteen channels with different semantics. It is not a drop-in substitute. We expanded the input convolution, initialized from TAESD, and trained all decoder weights against images from the original Qwen VAE.

The 1,229,443-parameter decoder completed 6000 updates using L1, local-window SSIM and finite-difference terms, with EMA weights. A 312/32 train/validation split gave mean PSNR 25.05 dB and SSIM 0.7996. It stores about 2.35 MiB in NCNN FP16 weights. Fine texture and colors can still change, especially beyond its small 384px teacher-data distribution.

Transformer output: normalized Inko latent z, shape [1, 16, H/8, W/8]

Exact Qwen decoder input: z × original_std + original_mean
Tiny Qwen decoder input:  z directly

Do not apply Stable Diffusion’s 0.18215 scale to this decoder.

The architecture did not become a 244M model: that pruning attempt failed. “Smaller” here means packed storage, lower residency and fewer forward evaluations, plus a much smaller trained decoder. The standalone bundle is still about 1.1 GiB on disk because it includes text assets and exact decoder graphs for multiple sizes.

CFG is a choice still under evaluation

The distilled student runs at CFG 1 because its targets already contain the teacher’s CFG-4.5 guidance. Additional CFG 2, 3 and 4.5 were tested afterwards; they require a second sequential model evaluation each step. Drew preferred CFG 2 in roughly 60% of cases and CFG 1 in roughly 40%. CFG 1.5 is an untested suggestion. The default and weights remain unchanged.

What is worth publishing?

  • The dense eight-step adapter and merged checkpoint: publish both for convenient use and reproducibility, with the exact base revision, eight-step training recipe and limitations. The adapter is about 75.4 MiB locally; it is smaller than the merged checkpoint but does not shrink runtime parameter count.
  • Tiny Qwen decoder as a separate artifact: its sixteen-channel normalized-latent contract and training recipe are independently useful. Clearly identify it as a lossy, locally trained TAESD-derived decoder for this Inko latent space, rather than a general Qwen or SD replacement.
  • The packed weights and portable runtime: the weight format and NCNN/NumPy runner belong together. GitHub is suitable for code, reports and compact metrics; a model host is suitable for larger arrays and checkpoint files. Label current CPU results as laptop measurements until ARMv7 validation is complete.
  • The exact decoder export and negative results: the one-frame specialization, workspace work and failed pruning/weight-edit experiments are useful engineering documentation. Rejected model checkpoints need not be promoted as releases.

No Hugging Face upload was made. Before a weight release, retain the base/encoder/decoder revisions and attribution, model-card settings, checkpoint hashes and evaluation limitations. The pinned local Inko card does not specify a license tag; resolve and document the upstream weight terms rather than assuming a source-code license covers every component. TAESD’s card declares MIT, while the other components have their own notices. Caption-data provenance is recorded; no public caption corpus is redistributed in this Git report.

Reproduce or resume without the clutter

The final dense checkpoint, all dense adapter checkpoints, final optimizer state, tiny decoder checkpoints, packed models, training trajectories, and exact runtime graphs remain local. Intermediate dense merges can be reconstructed from the original base plus each adapter; discarded exporter scratch can be regenerated from source. Retained final artifacts and original downloads remain outside Git.

Follow the commands in the experiment README. The current offline bundle includes a checksummed default recipe and the exact decoder fallback. The next deployment gate is a completed image on the actual Pi under its real memory and storage constraints, followed by worker integration and HDMI verification.
